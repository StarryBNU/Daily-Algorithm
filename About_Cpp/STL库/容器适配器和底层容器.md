在C++ STL中，**容器适配器**是一个非常有用的概念。我们可以从三个方面来理解它：

1. **什么是容器适配器？**
2. **它与底层容器的关系**
3. **STL中的常见适配器与`vector`、`list`、`deque`的关系**

---

## 1. 什么是容器适配器？

容器适配器是一种**设计模式**的体现——它**不直接实现数据存储**，而是**对现有容器（如`vector`、`deque`、`list`）进行包装**，提供一套**特定的、受限的接口**。这样做的目的是让用户只关注某种特定的数据结构行为，而无需关心底层如何存储。

- **栈（stack）**：只允许从一端（栈顶）插入和删除，后进先出。
- **队列（queue）**：只允许从一端（队尾）插入，从另一端（队头）删除，先进先出。
- **优先队列（priority_queue）**：每次弹出优先级最高的元素（通常基于堆实现）。

这些行为都是通过对底层容器的操作来实现的，但适配器**隐藏了底层容器的全部其他功能**，比如迭代器、随机访问等。

---

## 2. 容器适配器与底层容器的关系

**“适配器”依赖于一个“底层容器”**，这个底层容器才是真正存储数据的地方。适配器的每个成员函数实际上都是**调用底层容器的对应成员函数**完成的。我们可以把适配器想象成一个“外壳”，它内部包含了一个底层容器对象，然后对外提供经过裁剪的接口。

例如，`std::stack` 的典型实现可能像这样（简化版）：

```cpp
template <class T, class Container = std::deque<T>>
class stack {
    Container c;  // 底层容器对象
public:
    void push(const T& value) { c.push_back(value); }
    void pop() { c.pop_back(); }
    T& top() { return c.back(); }
    bool empty() const { return c.empty(); }
    // ...
};
```

你可以看到，`stack` 的 `push` 就是调用了底层容器的 `push_back`，`pop` 调用了 `pop_back`，`top` 调用了 `back`。它**没有自己分配内存**，所有存储工作都委托给了底层容器。

**关键点**：适配器对底层容器有**操作要求**，例如：
- 对于 `stack`：需要支持 `back()`、`push_back()`、`pop_back()`。
- 对于 `queue`：需要支持 `front()`、`push_back()`、`pop_front()`。
- 对于 `priority_queue`：需要支持随机访问迭代器（因为需要建堆），如 `[]`、`size()`、`push_back()`、`pop_back()`。

只要某个容器满足这些要求，它就可以作为该适配器的底层容器。这给用户带来了灵活性——你可以选择最适合你场景的容器。

---

## 3. STL中的适配器与 `vector`、`list`、`deque` 的关系

STL提供了三种容器适配器，每种都有默认的底层容器，但也可以显式指定其他容器。

### 3.1 `std::stack`（栈）
- **默认底层容器**：`std::deque`
- **可选底层容器**：`std::vector`、`std::list` 以及任何提供 `back()`、`push_back()`、`pop_back()` 的容器。
- **为什么默认用 `deque`？**  
  - `deque` 在尾部插入/删除是 O(1)，且不会像 `vector` 那样在扩容时复制所有元素（`deque` 是分段连续内存，扩容代价小）。  
  - 相比 `list`，`deque` 内存更紧凑，缓存友好，性能通常更好。

### 3.2 `std::queue`（队列）
- **默认底层容器**：`std::deque`
- **可选底层容器**：`std::list`（注意：不能使用 `vector`，因为 `vector` 没有 `pop_front` 操作）
- **为什么默认用 `deque`？**  
  - 队列需要从头部删除（`pop_front`）和尾部插入（`push_back`），`deque` 两端操作都是 O(1)，非常适合。  
  - `list` 虽然也支持两端操作，但内存不连续，额外开销较大，且缓存不友好。

### 3.3 `std::priority_queue`（优先队列）
- **默认底层容器**：`std::vector`
- **可选底层容器**：`std::deque`（需要支持随机访问迭代器，`list` 不支持随机访问，因此不能用）
- **为什么默认用 `vector`？**  
  - 优先队列基于堆实现，堆算法需要随机访问容器元素（如 `heapify` 操作需要下标计算），`vector` 满足随机访问，且内存连续，堆操作效率高。  
  - `deque` 也支持随机访问，但某些实现中可能略慢，不过也可用。

## 4. 一个直观的例子：切换底层容器

```cpp
#include <iostream>
#include <stack>
#include <vector>
#include <list>

int main() {
    // 使用 vector 作为底层容器的栈
    std::stack<int, std::vector<int>> s_vec;
    s_vec.push(1);
    s_vec.push(2);
    std::cout << s_vec.top() << std::endl;  // 2

    // 使用 list 作为底层容器的栈
    std::stack<int, std::list<int>> s_list;
    s_list.push(10);
    s_list.push(20);
    std::cout << s_list.top() << std::endl; // 20

    return 0;
}
```

无论底层容器是什么，`stack` 的用法完全相同。这就是适配器的好处：**接口统一，实现灵活**。

---

## 5. 总结

| 适配器           | 默认底层容器 | 可选底层容器          | 核心要求                          |
| ---------------- | ------------ | --------------------- | --------------------------------- |
| `stack`          | `deque`      | `vector`, `list`, ... | `back`, `push_back`, `pop_back`   |
| `queue`          | `deque`      | `list`                | `front`, `push_back`, `pop_front` |
| `priority_queue` | `vector`     | `deque`               | 随机访问迭代器                    |

- **底层容器**是真正存储数据的结构，如 `vector`、`deque`、`list`。
- **适配器**是对这些容器的封装，只暴露特定操作的接口。
- 它们的关系是：**适配器内部持有一个底层容器的实例，并通过转发成员函数调用来实现自身行为**。

理解这一点后，你就能更灵活地使用STL，也能根据性能需求选择合适的底层容器。
