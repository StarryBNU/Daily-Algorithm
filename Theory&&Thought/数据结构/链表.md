**链表不是数组**，它们是两种不同的数据结构。

虽然它们都用于存储一系列元素，但在**内存分配**、**访问方式**和**操作效率**上有本质的区别。

以下是详细的对比：

### 1. 核心区别：内存布局
-   **数组：** 需要**连续**的内存空间。
    -   它在内存中是一块完整的、连续的地址。
    -   例如：申请一个长度为 5 的数组，计算机会在内存中找一块连续的、能放得下 5 个元素的格子。
-   **链表：** 不需要连续的内存空间。
    -   它的每个节点可以散落在内存的各个角落。
    -   节点之间通过**指针**连接（就像寻宝游戏，找到第一个线索，里面藏着第二个线索的地址，以此类推）。

### 2. 访问方式
-   **数组：支持随机访问**
    -   如果你想访问第 10 个元素，直接通过下标 `arr[9]` 就能拿到。
    -   速度非常快，时间复杂度是 **O(1)**。
-   **链表：只支持顺序访问**
    -   如果你想访问第 10 个元素，你必须从第一个节点开始，沿着指针一个个数过去，直到找到第 10 个。
    -   速度相对较慢，时间复杂度是 **O(n)**。

### 3. 插入和删除操作
-   **数组：比较麻烦**
    -   如果你要在数组中间插入一个元素，你需要把后面的所有元素都往后挪一位，腾出空位。
    -   同理，删除一个元素后，需要把后面的元素都往前挪，填补空缺。
-   **链表：非常方便**
    -   如果你要在链表中间插入一个元素，只需要改变一下前后节点的指针指向，让它把新节点“链”进来即可，不需要移动其他元素。

### 4. 生活中的类比

-   **数组（电影院连坐）：**
    你和朋友们买电影票，必须买**连在一起的座位**。你可以很快找到 5 排 3 座在哪，但如果你朋友想插队坐到 2 排和 3 排中间，那就很麻烦，大家都要挪位置。
-   **链表（寻宝游戏）：**
    你手里有一张纸条，写着第一个线索的位置。你跑到那里，发现第二个线索的位置写在墙上；再跑过去，又发现了第三个线索的位置……你不能直接去第三个线索，必须按顺序找。

**有的，STL（标准模板库）里不仅有链表，而且还不止一种。**

最常用的是 **`list`**，它是一个功能强大的**双向链表**。此外，C++11 标准还引入了 **`forward_list`**，这是一个更节省内存的**单向链表**。

这里主要为你介绍一下最核心的 `list`。

### 1. 核心容器：std::list

`std::list` 是 STL 中实现双向链表的核心容器，你在大部分需要使用链表的场景下都会用到它。

*   **本质**：它是一个**双向链表**。每个元素（节点）都包含了数据以及指向前一个和后一个元素的指针。
*   **头文件**：使用前需要包含 `<list>`。
*   **命名空间**：它定义在 `std` 命名空间中。

为了让你更直观地理解 `list` 的特点，我把刚才聊到的数组（以 `vector` 为例）和 `list` 做个对比：

| 特性              | std::vector (动态数组)      | std::list (双向链表)                           |
| :---------------- | :-------------------------- | :--------------------------------------------- |
| **内存结构**      | 连续内存空间                | 非连续内存，节点通过指针连接                   |
| **随机访问**      | **支持**，O(1) 时间复杂度   | **不支持**，只能顺序遍历，O(n)                 |
| **中间插入/删除** | **慢**，需要移动大量元素    | **极快**，O(1)，只需修改指针                   |
| **头尾插入/删除** | 尾部快，头部慢              | 两端都非常快（有 `push_front/pop_front`）      |
| **迭代器稳定性**  | 插入/删除可能导致迭代器失效 | **很稳定**，除被删除元素外，其他迭代器依然有效 |

### 2. `list` 的常用操作速览

`list` 提供了丰富的成员函数，让你能方便地操作数据。

*   **构造与赋值**
    *   `list<int> l1;`          // 构造一个空链表
    *   `list<int> l2(5, 10);`    // 构造一个包含5个值为10的元素的链表
    *   `list<int> l3(l2);`       // 拷贝构造

*   **元素访问**
    *   `l1.front();`   // 访问第一个元素
    *   `l1.back();`    // 访问最后一个元素
    *   `l1.begin();` / `l1.end();` // 获取正向迭代器

*   **容量相关**
    *   `l1.empty();`   // 判断链表是否为空
    *   `l1.size();`    // 返回链表中的元素个数

*   **增删元素**
    *   `l1.push_back(20);`   // 在尾部插入20
    *   `l1.push_front(10);`  // 在头部插入10
    *   `l1.pop_back();`      // 删除尾部元素
    *   `l1.pop_front();`     // 删除头部元素
    *   `l1.insert(pos, 100);` // 在迭代器pos指向的位置插入100
    *   `l1.erase(pos);`      // 删除迭代器pos指向的元素

*   **特有操作** (这些是链表才有的高效操作)
    *   `l1.splice(pos, l2);`    // 将链表l2的元素转移到l1的pos位置（常数时间）
    *   `l1.sort();`              // 对链表进行排序 
    *   `l1.unique();`            // 删除链表中相邻的重复元素 
    *   `l1.reverse();`            // 反转链表 
    *   `l1.remove(10);`           // 删除链表中所有值为10的元素 

### 3. 另一个选择：std::forward_list

如果你对内存占用非常敏感，并且只需要单向遍历，可以考虑 C++11 引入的 `forward_list`。

*   **本质**：**单向链表**。每个节点只有指向下一个节点的指针。
*   **特点**：比 `list` 更节省内存，但只能向前遍历，没有 `rbegin()`、`rend()` 等反向迭代器，也没有 `size()` 方法。

### 总结

简单来说，STL 不仅提供了链表，还针对不同场景提供了两种选择：
*   大部分情况下，使用功能全面的 **`std::list`**（双向链表）即可。
*   如果特别在意内存开销且只需单向操作，可以选择 **`std::forward_list`**（单向链表）。

邻接矩阵和邻接表是图论中两种最基本的存储结构，它们的核心区别在于**内存占用**和**操作效率**，适用于不同类型的图。

---

## 1. 定义
- **邻接矩阵**  
  使用一个 `V × V` 的二维数组 `matrix` 存储图。  
  `matrix[i][j]` 表示顶点 `i` 到顶点 `j` 的边信息（如是否存在、权重等）。无权图常用 `0/1` 表示，带权图则存储权值（无边时用无穷大或 `0`）。

- **邻接表**  
  为每个顶点维护一个链表（或动态数组），存储与该顶点直接相连的所有邻接点及边信息。  
  通常表示为一个长度为 `V` 的数组，每个元素是一个列表（如 `vector<pair<int, int>>` 或 `list`），记录邻接点编号和权值。

---

## 2. 空间复杂度
| 存储结构 | 空间复杂度   | 说明                                                         |
| -------- | ------------ | ------------------------------------------------------------ |
| 邻接矩阵 | **O(V²)**    | 固定占用 V² 个单元，与边数 E 无关。对稀疏图浪费空间，对稠密图紧凑。 |
| 邻接表   | **O(V + E)** | 存储顶点数组 + 每条边存储一次（无向图每条边存两次）。对稀疏图友好。 |

---

## 3. 常用操作的时间复杂度
| 操作                       | 邻接矩阵                           | 邻接表                                          |
| -------------------------- | ---------------------------------- | ----------------------------------------------- |
| **判断两点是否相连**       | O(1) 直接访问矩阵元素              | 最坏 O(V)（需遍历邻接链表）                     |
| **遍历某顶点的所有邻接点** | O(V) 扫描整行                      | O(度(v)) 仅遍历该顶点的邻接链表，对稀疏图高效   |
| **添加一条边**             | O(1) 直接赋值                      | O(1) 在链表头或尾部插入（若需判重则可能 O(度)） |
| **删除一条边**             | O(1) 直接置零/无穷大               | 最坏 O(度) 需查找并删除                         |
| **添加一个顶点**           | O(V²) 需重新构建矩阵（复制原矩阵） | O(1) 只需在数组末尾追加一个空链表               |

---

## 4. 适用场景
- **邻接矩阵**  
  - **稠密图**（E 接近 V²）时，空间利用合理，且能快速判断边是否存在。  
  - 需要频繁检查任意两点间是否有边的算法（如 Floyd-Warshall 全源最短路）。  
  - 图的规模较小（V 通常 ≤ 5000）时，简单易实现。

- **邻接表**  
  - **稀疏图**（E 远小于 V²）时，能大幅节省内存。  
  - 需要**遍历某顶点的所有邻接点**的算法（如 BFS、DFS、Prim、Kruskal 等），能获得与度成正比的时间。  
  - 图的规模很大（V 可达 10⁵ 甚至更大）时，是唯一可行的存储方式。

---

## 5. 其他对比
- **实现复杂度**：邻接矩阵实现简单直观；邻接表稍复杂，但现代语言（如 C++ 的 vector）可轻松实现。
- **处理带权图**：两者均支持，只需在矩阵元素中存储权值，或在邻接表的节点中增加权值字段。
- **多重边**：邻接矩阵只能保留一条边（会覆盖）；邻接表可以存储多条平行边（如果允许）。
- **对称性**：无向图的邻接矩阵是对称矩阵，可压缩存储；邻接表无此特性，但每条边存两次。

---

## 6. 总结
| 特性         | 邻接矩阵         | 邻接表                   |
| ------------ | ---------------- | ------------------------ |
| 空间         | O(V²)            | O(V + E)                 |
| 判断两点相连 | O(1)             | O(度)                    |
| 遍历邻接点   | O(V)             | O(度)                    |
| 适用图类型   | 稠密图、小规模图 | 稀疏图、大规模图         |
| 常用算法     | Floyd、传递闭包  | BFS、DFS、Prim、Dijkstra |

**选择建议**：  
- 若图较稠密或顶点数较小，选邻接矩阵，代码简单且操作快捷。  

- 若图稀疏或顶点数很大，选邻接表，节省内存且遍历邻接点高效。
