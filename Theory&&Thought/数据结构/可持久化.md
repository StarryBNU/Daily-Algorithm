在算法竞赛中，**可持久化数据结构** 是指能够保留所有历史版本的数据结构。每次修改操作不改变原有数据，而是生成一个新的版本，新旧版本共享不变的部分。这使得我们可以高效地查询任意历史时刻的状态，常用于解决区间查询、离线回溯、多版本维护等问题。

## 核心思想
- **版本**：每个操作产生一个新版本，用一个整数（版本号）标识。
- **节点复用**：修改时只复制被修改的节点及其祖先，未改变的节点直接复用旧版本中的节点。
- **动态开点**：节点在需要时才创建，节省空间。

## 常见可持久化数据结构

### 1. 可持久化数组
- **原理**：用可持久化线段树（或平衡树）实现，将数组下标看作线段树的下标，每个叶子存储值。
- **操作**：
  - 查询某版本中某位置的值：递归到叶子。
  - 修改某位置的值：复制路径上的节点，更新叶子，返回新根。
- **复杂度**：时间 O(log n)，空间 O(m log n)（m 为修改次数）。

### 2. 可持久化线段树（主席树）
- **最常用**，通常用于处理**静态区间第 k 小/大**问题。
- **思想**：对序列的每个前缀建立一棵权值线段树，记录前缀中每个值出现的次数。第 i 棵树基于第 i-1 棵树修改一个位置得到。
- **查询区间 [l, r]**：用第 r 棵树减去第 l-1 棵树（对应节点权值相减），然后在差值树上二分查找第 k 小。
- **实现技巧**：动态开点，每个节点存储左右孩子指针和区间和。
- **复杂度**：建树 O(n log n)，查询 O(log n)，空间 O(n log n)。

### 3. 可持久化 Trie
- **应用**：处理与异或相关的区间问题，如最大异或和、区间异或第 k 大。
- **思想**：对每个前缀建立一棵 Trie（二进制树），存储前缀中所有数的二进制位。查询区间时用两棵 Trie 相减（节点计数相减），然后在 Trie 上贪心走位。
- **复杂度**：O(n log C)，C 为值域大小。

### 4. 可持久化并查集
- **作用**：支持在历史版本上合并和查询（如离线动态连通性）。
- **实现**：用可持久化数组存储每个节点的父节点（fa）和子树大小（size 或秩）。合并时找到根，然后将 size 小的根指向大的根，并更新 size。注意不能路径压缩（破坏可持久化），只能按秩合并。
- **复杂度**：每次操作 O(log^2 n)（查询根需 O(log n) 次递归，每次递归访问可持久化数组 O(log n)），空间 O(m log n)。

## 实现技巧
- **节点结构**：通常包含左孩子指针（`l`）、右孩子指针（`r`）、维护的信息（如和、计数）。
- **版本根数组**：`root[i]` 存储第 i 个版本的根节点编号。
- **动态开点**：每次修改时，复制当前节点，并递归修改孩子，返回新节点编号。
- **空间估算**：主席树一般需要 `n * 4 + m * log n` 的节点数，通常开 20~40 倍空间。

## 经典应用举例

### 静态区间第 k 小（主席树）
```cpp
// 建树
int build(int l, int r) {
    int p = ++tot;
    if (l == r) return p;
    int mid = (l + r) >> 1;
    lc[p] = build(l, mid);
    rc[p] = build(mid + 1, r);
    return p;
}
// 插入
int update(int pre, int l, int r, int pos) {
    int p = ++tot;
    lc[p] = lc[pre]; rc[p] = rc[pre]; sum[p] = sum[pre] + 1;
    if (l == r) return p;
    int mid = (l + r) >> 1;
    if (pos <= mid) lc[p] = update(lc[pre], l, mid, pos);
    else rc[p] = update(rc[pre], mid + 1, r, pos);
    return p;
}
// 查询 [u, v] 区间第 k 小
int query(int u, int v, int l, int r, int k) {
    if (l == r) return l;
    int mid = (l + r) >> 1;
    int x = sum[lc[v]] - sum[lc[u]];
    if (k <= x) return query(lc[u], lc[v], l, mid, k);
    else return query(rc[u], rc[v], mid + 1, r, k - x);
}
```

### 可持久化数组支持版本回退
- 维护多个版本，每次修改返回新版本根。
- 查询时传入版本根，递归访问。

### 可持久化并查集解决连通性问题
- 常用于离线算法（如「CEOI 2017」Building Bridges），需要回溯历史状态。

## 注意事项
1. **空间开销**：可持久化数据结构会消耗较多内存，务必根据数据范围估算节点数，开够数组（通常 `N * 20` 到 `N * 40`）。
2. **递归深度**：递归建树/查询时深度为 O(log n)，一般安全；但若数据范围大（如值域 1e9）需离散化。
3. **版本编号**：通常从 0 开始，0 号版本为空树。
4. **是否支持修改**：主席树一般用于静态前缀（不支持修改原序列），若要支持修改需要使用树状数组套主席树（带修主席树），但复杂度更高。

## 总结
可持久化是竞赛中处理历史版本问题的利器，掌握其核心思想（节点复制、动态开点、版本相减）后，可以灵活扩展到各种数据结构。最常见的应用是主席树解决静态区间第 k 大问题，在此基础上可进一步解决树上路径第 k 大、动态区间等问题。
